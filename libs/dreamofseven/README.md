# 梦幻七域 (The Dream of Seven / dreamofseven)

台湾团队自 1999 年开发的 BIG5 编码 MUD，源代码开机横幅自述"其精神源自 ES2 Mudlib 架构，特此感谢 Annihilator"——和本项目已收录的 `hell`/`zhyx` 等同属 ES II/Annihilator 血统，但只继承了最早期的 "original from Lil / rewritten by Annihilator"一支，没有后续"Doing Lu"/"yh2003"分支的痕迹，是一支更早、更独立的旁支分叉。

## 内容亮点

- 一款拥有两大区域（world1/world2）的大型武侠世界，内容体量约 3.3
  万个文件，由许多不同巫师各自开发的地图拼接而成，其中巫师 "tmr"
  一人贡献了整整十余个独立分区（巴托吉亚、荒地、地下洞窟、独立森林
  /港口/村落、迷雾森林、鲸鱼森林/河流、野人岛、全真教等）。
- 注册流程：英文账号名 → 确认建立 → 中文名字 → 密码 → 确认密码 →
  Email → 选择种族（人类/仙派/妖魔/兽人/虎人/泰坦）→ 确认 → 性别
  → 进入游戏世界，落在起始场景"朝天楼"（一间位于"朝天湖"畔的客栈），
  场内有新手导师和店小二两位 NPC 迎接新玩家。

## 本次修复的关键 bug

- `master.lpc` 的 `log_error()` 完全没有区分"警告"和"真正的错误"
  （比同宗 `zhyx`/`naruto` 已知的"大小写判断失误"还要严重，属于
  `revive` 那种"压根没有判断逻辑"的变体），导致每一次场景/NPC 懒
  加载编译产生的任何警告都会原样广播给当时在线的玩家。已加上大小写
  不敏感的 "warning" 子串判断。
- **严重 bug（波及全局）**：`master.lpc` 的 `preload()` 函数（驱动
  开机时逐一加载每个常驻精灵的入口）用 `file_size(file+".c")` 判断
  文件是否存在——本项目标准的 `.c`→`.lpc` 改名流程之后，这个判断
  永远为假，会导致 `securityd`/`virtuald`/`logind`/`chinesed` 等
  **全部常驻精灵静默地永远无法加载**，且没有任何报错。同样的写法
  也出现在核心的物件生成函数 `new_ob()`（几乎每一个 NPC/道具的
  生成都要经过它）里，会让**全服所有房间的 NPC/道具生成失效**。
  好在这两处（连同另外约 60 处类似写法）都恰好是独立的字符串字面量
  `".c"`，被本项目转换脚本的字面量替换步骤顺带自动修正——本次仅在
  开机测试前逐一人工核实修正是否生效，未额外编写代码。
- 房间物件生成函数 `roomd.lpc::make_inventory()` 原本没有对生成失败
  （例如 NPC 引用了档案里没有实作的技能）加保护，一个道具/NPC 生成
  失败会导致**整个房间加载失败**；已仿照本项目一贯的"房间填充保护"
  写法加上 catch() 和优雅降级。
- `is_chinese()`/`check_legal_name()` 的经典 BIG5 字节长度误判（本
  驱动按字符而非字节计数），已按本收藏的既定手法修正。
- 原始 BIG5 源码里发现约 27 处"字符串结尾多打了一个反斜杠"的作者
  笔误（例如 `"鐵蓋\");`），会吞掉字符串本该有的结束引号、拖垮后面
  一大段代码的语法解析；逐一确认并修正，不属于转码引入的问题。

详见 `NOTES.md`。
