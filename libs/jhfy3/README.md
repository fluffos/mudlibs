# 江湖风云3 (jhfy3)

游戏内标题为"夕阳再现 之「风云再起Ⅱ」"，是 [jhfy2](../jhfy2/) 的后续/扩展版本（7977/9332 个 jhfy2 文件按路径重合，jhfy3 在此基础上大幅扩充了内容），沿用 jhfy2 的金庸门派/地图世界观。天赋数值同样是六项，其中"福缘""容貌"为隐藏属性；注册采用管理密码+普通密码的双密码机制，比 jhfy2 的单一密码更严格。死亡/复活系统与 `jhfy`/`jhfy2` 共享同一套代码，实测完整的战斗→死亡→鬼门关→白无常五阶段对白→复活落地"武庙"全程顺畅，无需人工干预。虽然文件路径和 `jhfy2` 高度重合，但这份档案的 `d/city/sj.lpc`（"世界之巅"跳崖场景）实际上和 `jhfy2` 所属的"天涯"家族版本不同，而是和 `xajh4gkb`（笑傲江湖4公开版，同样打着"夕阳再现"旗号）、`xyzx`（夕阳再现，同一品牌的源头版本之一）逐字节相同——说明"夕阳再现"是独立于"天涯"的另一个代码血统，这份档案是站在 `jhfy2` 的地图基础上、换用了"夕阳再现"这一支的核心系统文件。

## 注册流程

英文名字（3-10 个英文字母）→ 确认建立新角色（y/n）→ 中文名字（直
接输入完整姓名）→ 管理密码（至少 5 位）→ 确认管理密码 → 普通密码
→ 确认普通密码 → 天赋数值（六项属性，其中福缘、容貌为隐藏属性；
输入 0 交由系统随机产生，随后需再输入 y 确认这组数值）→ 电子邮件
地址 → 性别（m/f）→ 进入游戏世界。

**注意**：这份档案采用管理密码+普通密码的双密码机制，和
[jhfy2](../jhfy2/) 的单一密码不同。

## 本次修复的关键 bug

- `adm/daemons/logind.lpc` 的 `logon()`：经典的服务器启动宽限期
  检查 `if (uptime() < 30)`（AGENTS.md §1.3e）——WASM 沙箱每次连线
  都是紧接着驱动启动之后，这个检查每次都必然触发，而且由于 WASM
  的事件驱动机制是由宿主逐笔驱动而非真实系统时钟驱动，靠等待真实
  时间流逝也无法满足这个条件。已按项目标准做法，对
  `127.0.0.1`（本地/WASM 测试连线）放行，保留对其余 IP 的原始检
  查不变。
- `adm/daemons/logind.lpc` 的 `enter_world()`：食物/饮水初始化闸门
  检查了错误的物件（`ob->query("age")` 应为 `user->query("age")`，
  AGENTS.md §8.9），已修正——注：本档案有独立的 `heal_up()` 兜底逻
  辑会自动填满未成年角色的食物/饮水，所以此 bug 实际观感上是"哑
  的"，但仍按既定原则修正底层错误读取。
- `adm/daemons/logind.lpc` 的取名流程有两处裸 `printf("%O\n", ob)`
  调试残留（AGENTS.md §7.34），会把物件引用直接打印给正在注册的玩
  家看，已删除。
- **新发现（AGENTS.md §7.100）**：§7.86 记录的"`inherit X` 之后又
  多余 `replace_program(X)`导致该物件永久无法绑定自身闭包"的致命
  形状，在本档案里不止出现在留言板上，`ROOM` 房间基类本身也有同样
  的写法，全档案约 5,591 处活跃实例（约六成的房间文件）。已修复其
  中 1 个有实测证据的房间、造房工具 `roommaker.lpc` 自身生成新房间
  的两处代码模板（避免继续生产带 bug 的新房间）、以及 3 个抽样验
  证档案，共 6 个档案；**其余约 5,585 个房间档案因规模过大、本轮
  自动化批量改写被执行安全机制拦下而未能处理，留给未来专门一轮分
  批修复**（详见 `NOTES.md` 与 AGENTS.md §7.100）。

没有发现 Chinese 姓名判断、宏定义不匹配或指令表相关的 bug。
