# 泥潭6 win_nodb版 (nt6nitan6win)

[nt6](../nt6/) 的同源版本（同一个 lineage/master hash，源码逐字节相同），无数据库（win_nodb）打包变体。共享 nt6 那个以创世神话（盘古开天、太极两仪）为背景、从长安、洛阳等中原城池一路延伸到安南（越南）、高丽（朝鲜）、哈萨克、台湾等边疆/海外场景的大地图，以及"注册房间"配"出生仪式"的角色生命周期设计，另外还有自己独立的"重生"（`d/reborn/`）场景。

## 本次修复的关键 bug

和 [nt6](../nt6/) 完全相同的三类 bug（详见该 lib 的 README 完整
说明）：

1. `feature/dbase.lpc` 的 `set()`/`query()`/`delete()`（及
   `_temp` 版本）函数本体缺失——档案自己的注释声称已经修好，但实
   际代码从未补上，导致所有走 F_DBASE 的物件的裸 `set()`/
   `query()` 调用命中 simul_efun 的全局共享后备 dbase。
2. `logind.lpc`/`named.lpc` 里第二处漏网的 §8.1 GBK 字节数未减半
   bug，导致单字姓氏/单字给名（如"风"）被误判为"太长"或"空名
   字"。
3. `user.lpc`/`baby.lpc`/`giftd.lpc`/`examined.lpc`/`room.lpc` 里
   用 `efun::set/query/addn/delete(...)` 想要调用被局部覆写前的
   版本，但这些函数从来都不是这个驱动的真正内建 efun，改用
   `::set`/`::query`/`::delete`（或对 `addn` 直接改用
   `ob->add(...)`/`::add`）。

由于这份档案的每一个受影响文件都和 nt6 修复前完全一致，本次直接把
nt6 已验证过的修复版本档案原样复制过来，而不是重新推导一遍相同的
补丁；随后在这个 lib 自己身上独立跑了一次完整的 WASM 注册验证（而
不是只信任 nt6 那边的验证结果），确认结果一致。

## 注册流程

和 [nt6](../nt6/) 相同：英文名字（3-10 个英文字母）→ 确认建立新
角色（y/n）→ 中文姓氏（1-2 个汉字，可留空）→ 中文名字（1-2 个汉
字）→ 管理密码（至少 5 位）→ 确认管理密码 → 普通密码（至少 3
位，不能和管理密码相同）→ 确认普通密码 → 性别（m/f）→ 进入游戏世
界。

## 本地运行

```
cd libs/nt6nitan6win
~/src/fluffos/build-debug/src/driver config.fluffos
```

游戏端口：**40187**。和 nt6 一样，分布式预载耗时较长，本地或浏览
器测试连线后请耐心等待约 30 秒再输入英文名字。
