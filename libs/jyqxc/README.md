# 金庸群侠传 (jyqxc)

游戏内标题为 "The Story of Hero"，金庸题材武侠世界，地图相对精简，
涵盖华山、武当、少林、丐帮、峨嵋、明教等门派场景。天赋数值（膂力、
悟性、根骨、身法）由系统整体随机产生，只能全盘接受或重掷，不支持
逐项自选；内置的"新手指南"（`help newbie`）其实是一篇玩家自己写的
攻略，细讲"较量"（气/精跌到 50% 自动停手）和"死战"（`kill`，真刀
真枪打到死）两种战斗指令的区别。小说里的反派会直接站在普通街道上，
例如白驼山少庄主欧阳克，战力远超新手能应付的范围，一言不合就可能
一击致命。死亡后会被押往鬼门关，除常见的黑白无常外，还有一位不算
常见的"实习无常"NPC 同行接引。与本项目里的 `jyqxc2`、
`jyqxc2013fwq`、`fy2mg`、`xkx2017` 共享同一份 `master.lpc`
（"金庸群侠传"/XKX 框架家族）。

## 内容亮点

- 全库约 49 个留言板都用一种驱动无法解析的旧式紧凑二进制存档格式
  （魔术字节 `#inh`/`?inh`），一旦房间摆了留言板，`look` 就会因为
  存档解析失败连带清空物件属性而崩溃——本次没有反解这些旧存档（那
  属于内容修复），而是让显示名称逻辑在缺少 `id` 属性时优雅降级。

- **更正（2026-08-05）**：上面提到的"7.68 复活软锁"修复已经撤销——经重新评估，鬼魂"不在场"时放弃复活流程更可能是有意的游戏设计（多数这类档案里鬼魂本身就无法自行移动，离开是一种游荡机制，回来时 init() 会重新触发流程），不是需要强制重试的 bug；详见 NOTES.md。

## 注册流程

英文名字（3-12 个英文字母）→ 确认建立新角色（y/n）→ 中文名字（1-6
个中文字）→ 密码（至少 5 位）→ 确认密码 → 系统自动产生一组天赋数
值（膂力、悟性、根骨、身法），直接询问是否接受（y/n，不接受会重新
产生一组）→ 电子邮件地址 → 性别（m/f）→ 进入游戏世界。

## 本次修复的关键 bug

- `feature/name.lpc` 的 `short()`：在没有设定 `"short"` 属性时，会
  用 `capitalize(query("id"))` 拼出预设显示名称，但没有检查
  `query("id")` 是否真的是字符串。这个 lib 里约 49 个留言板（clone
  自 `inherit/misc/bboard.lpc`）的存档文件 `data/board/*.o` 用的是
  一种旧式的紧凑二进制存档格式（文件开头是 `#inh`/`?inh` 这样的魔术
  字节），本驱动的 `restore_object()` 完全无法解析，会抛出 "Illegal
  file format" 例外；而这个例外抛出前，驱动已经把该物件的整个
  dbase 属性表清空（包括 `create()` 里刚设定好的 `"id"` 属性），于
  是只要房间里摆了一个留言板，一进房间 `look` 就会因为
  `capitalize()` 收到非字符串参数而崩溃。没有去反解这 49 个旧存档
  文件的二进制格式（那属于内容修复而非程式 bug），而是让 `short()`
  在 `id` 不是字符串时优雅降级，不再依赖它拼名字。

没有发现 Chinese 姓名判断、宏定义或指令表相关的 bug——`is_chinese()`
本来就用正确的 Unicode 码点区间判断；`check_legal_name()` 里有一个
`i%2==0` 隔字检查的历史遗留写法，会让位于奇数位置的非中文字符漏
检，但因为真正的中文名字每个字都是中文，不会被这个写法误判为不合
法，所以不影响真实注册流程，未做修改。
