# 风云III (3.0)

与 151/fy2mg 同为 `jinyongqunxiazhuan`/XKX 框架家族成员（登录流程、
`check_legal_name`、密码复杂度要求、民族选择等均字节级相同），但游戏
内容和标题不同，与本合集里其它"风云"系 lib（fy2/fys/fysjmb/jhfy2/
jhfy3/fyzfqyy/fy2qh/fy3dz/fy3xd/
jhfy/zzfy/zzfy3/fengyun434/fy2005）也无 master-hash 匹配。

## 内容亮点

- 和 `fy2mg`（风云II美国版本）同属"金庸群侠传"/XKX 框架家族，登录
  流程、密码复杂度要求、民族选择等字节级相同，但和本合集里其它
  "风云"系档案（`fy2`/`fys`/`jhfy2`/`jhfy3`/`zzfy3` 等）都没有代码
  匹配，是这批"风云"系里又一个独立分支。
- 新手起始房间"凤求凰客栈"有持续的 NPC 心跳对话，气氛比一般的静
  态新手房更热闹（但也因此测试脚本容易被岔开话题，详见下方说明）；
  新角色会在几个候选起始房间（凤求凰客栈/沉香镇中心/小客栈/迎梅客
  栈）里随机落地。
- 战斗中气血降到临界值会触发角色自动逃跑的安全机制，实测对多个不同
  强度的敌人都可靠生效，不容易在正常战斗中真的被打死。
- 少林寺一支的拜师体系有完整的门派辈分链（十五代到二十三代弟子/
  长老/掌门都各有专属 NPC），现任掌门要求先完成一段隐藏考验
  （`won_master_yi`）才会收徒——不是随便找个和尚就能拜师。

## 深度功能测试新发现的 bug（详见 NOTES.md）

`adm/daemons/logind.lpc` 里有两处调试用的 `printf("%O\n", ob)`
（AGENTS.md §7.34，两条平行的姓名输入路径各一处）——已删除。另外在
死亡/复活系统里发现并修复了 AGENTS.md §7.68 归档的复活软锁死 bug 类
的又一实例：`d/death/npc/panguan.lpc`（朱笔判官）的 `death_stage()`
把"对象已不在场"和"对象已销毁/战力超限"这两种本质不同的情况混在
同一个 `return` 里处理，导致复活序列一旦被打断就会永久卡死。已按
已验证过的修法拆分；本轮测试里角色的自动逃跑机制一直没让角色真正
死亡，所以这个修复是照抄其他姊妹档案已验证过的修法应用的，未在
`fy330` 本身现场复现死亡→复活的完整流程。

## 注册流程

`new` 触发注册 → 英文 id（3-10 个英文字母）→ 确认创建（y/n）→ 中文
名字（1-6 个中文字，留空则随机取名）→ 密码（需同时包含大写字母、
小写字母和特殊符号）→ 确认密码 → 电子邮件地址 → 性别（m/f）→ 民族
选择（0=汉族，1=苗族，2=满族，3=蒙古族）。

新手起始房间"凤求凰客栈"里有活跃的 NPC 心跳对话，如果用脚本化测试
（`--idle` 触发发送）在刚进入房间后立即测试 `quit`，NPC 对话可能会
不断刷新输出、延后满足静默阈值的时机——这不是 bug，多给几条中间指令
（例如先 `look`/`score`）就能正常触发。

## 本次修复的关键 bug

（与 151/fy2mg 完全相同）

- `adm/daemons/logind.lpc`：`make_body()` 里的 `seteuid(getuid())` 会
  把 `create()` 刚设置好的 euid 重置为空字符串，已改为显式
  `seteuid(ROOT_UID)`。
- `check_legal_name()`：沿用旧版 GBK 字节长度界，已改为按字符数
  （1-6）+ 逐字符 `is_chinese()` 判断。
- `adm/daemons/securityd.lpc`：`get_status()` 加了防御性
  `mapp()`/`arrayp()` 检查。
