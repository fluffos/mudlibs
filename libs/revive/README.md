# 终极地狱-轩辕传说 (revive)

游戏内标题为 "EMPEROR OF ULTRA HELL(BLOOD & MAGIC) FROM 1999.12.12"，和本项目已收录的 `hell`（游戏内标题 "REVIVE OF ULTRA HELL...FROM 1999.11.13"）同属 Doing Lu 的"地狱"血统家族（master.lpc 的作者传承注释一字不差），但这份 GitHub 上的 `revive` 仓库是一份规模小得多的 "底层代码"发行版——仓库自述即为"mud 底层代码"，只随附了投胎/阎罗殿 (`death`)、比武场 (`pk`) 和注册入口 (`register`) 三个地图分区，原版 `hell` 里的近 54 个门派/城市地图（武当、少林、峨嵋、大理、丐帮……）和整个武功技能树都没有包含在这份发行版里。

## 内容亮点

- 注册流程和同宗 `hell`/`zhyx` 完全一致：英文账号名（3-10 个英文
  字母）→ 确认建立 → 中文姓氏（可留空）→ 中文名字 → 管理密码 →
  确认 → 普通密码 → 确认 → 角色资质（1-5，猛士/智慧/耐力/敏捷/
  均衡）→ 性别（m/f）→ 进入游戏世界，落在"世外桃源"入口场景，水笙
  NPC 会主动提醒"你还没有注册，快注册(register)吧"——完整的"投胎"
  仪式（`register`/`decide`/选品性/`wash`/`born`）沿用同一血统的
  设计，此前 `score` 显示"还没有出生呐"是正常游戏设计，不是 bug。
- 虽然只是"底层代码"版本，核心引擎（姓名系统、频道系统、留言板、
  门派 dbase 存档架构、投胎流程）都是完整的，可以正常游玩注册
  流程本身；但由于地图内容大幅缺失，投胎后能去的目的地非常有限。

## 本次修复的关键 bug

- `master.lpc` 的 `log_error()` 完全没有区分"警告"和"真正的错误"，
  比同宗 `zhyx`/`naruto` 已知的"大小写判断失误"还要严重——这份档案
  里根本没有任何判断逻辑，导致每一次场景/NPC 懒加载编译产生的任何
  警告都会原样广播给当时在线的玩家。已加上大小写不敏感的
  "warning"子串判断。
- `is_chinese()`/`check_legal_name()`/`named.lpc` 的经典 GBK 字节
  长度误判（本驱动按字符而非字节计数），已按本收藏的既定手法修正。
- 严重 bug：`calc_sec_id()`（角色存档完整性校验）在这份档案里从未
  被真正实现，永远回传固定字串 `"none"`，导致存档校验永远无法通过，
  **任何玩家在驱动重新开机之后都无法再次登录自己已经创建的角色**
  （报错"无法读取你的数据档案，您需要和巫师联系"）。已比照同宗
  `hell` 里这个函数真正实现所使用的 `crypt()` 配对写法，让这个尚未
  实作的占位函数变成真正的空操作，而不是必然失败的陷阱——不涉及
  编造任何游戏内容或校验算法本身。
- `virtuald.lpc` 的虚拟房间判断把"文件不存在"误判成"文件存在"，导致
  任何指向这份精简版缺失内容的引用都会陷入无限递归，触发
  "Inherit chain too deep"；连带修复了房间物件生成函数缺少保护的
  问题——这两个 bug 叠加在一起，此前会让**每一个全新玩家的注册流程
  在进入游戏世界的最后一步就静默失败**。

详见 `NOTES.md`。
