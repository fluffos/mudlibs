# 金庸群侠传 (jyqxc2)

[jyqxc](../jyqxc/) 的姊妹版本（编号 086/087），逐文件比对确认二者实质上是同一份原始数据的两份几乎完整快照——`master.lpc`、 `securityd.lpc` 及整个死亡系统逐字节相同，压缩包文件名带有典型的浏览器重复下载"(1)"后缀，应是同一次下载被误判为两份独立档案。游戏内容与 jyqxc 完全一致：精简的金庸门派地图（华山、武当、少林、丐帮、 峨嵋、明教），白驼山少庄主欧阳克等原著反派直接游荡在街头，死亡后经鬼门关由黑白无常及"实习无常"接引复活。

## 内容亮点

- **与 `jyqxc` 的关系：确认为几乎完整的重复归档，非独立衍生**。
  `work/` 目录树（各约 3690 个文件）用 `diff -rq` 比对只有 3 处差异
  ——`adm/daemons/logind.lpc`（`jyqxc2` 携带的是 `jyqxc` 自己修复前

  角色存档；`adm/single/master.lpc`、`adm/daemons/securityd.lpc`、
  整个 `d/death/` 死亡区逐字节完全相同。原始压缩包也几乎一致（仅
  `jyqxc2` 那份多一个 `svr.exe`），归档文件名
  `金庸群侠传.rar`/`金庸群侠传 (1).rar` 的 `(1)` 后缀是典型的浏览器
  重复下载模式——这两份archive 很可能是同一次下载的两份拷贝，只是没
  被本项目原有的去重流程识别出来（详见 AGENTS.md §11）。
- 踩中和 `jyqxc` 完全相同的留言板旧存档格式 bug（这次是约 18 个留

- §10.7 深度测试额外发现并修复了两个和 `jyqxc` 逐字节相同的 bug
  （`jyqxc2` 的 `logind.lpc` 当时还是 `jyqxc` 修复前的原始版本，见
  下「本次修复的关键 bug」），并现场走完一次完整的死亡→复活流程。

## 注册流程

英文名字（3-12 个英文字母）→ 确认建立新角色（y/n）→ 中文名字（1-6
个中文字）→ 密码（至少 5 位）→ 确认密码 → 系统自动产生一组天赋数
值（膂力、悟性、根骨、身法），直接询问是否接受（y/n，不接受会重新
产生一组）→ 电子邮件地址 → 性别（m/f）→ 进入游戏世界。

## 本次修复的关键 bug

和 [jyqxc](../jyqxc/) 完全相同的 bug：`feature/name.lpc` 的
`short()` 在没有设定 `"short"` 属性时会用
`capitalize(query("id"))` 拼出预设显示名称，但没检查
`query("id")` 是否为字符串。这个 lib 里约 18 个留言板（clone 自
`inherit/misc/bboard.lpc`）的存档文件 `data/board/*.o` 用的是同一
种旧式紧凑二进制存档格式（`#inh`/`?inh` 魔术字节），本驱动的
`restore_object()` 无法解析，抛出例外前会把该物件的整个 dbase 属
性表清空（包括刚设定好的 `"id"`），于是只要房间里摆了留言板，一
进房间 `look` 就会崩溃。修法同 jyqxc：让 `short()` 在 `id` 不是字
符串时优雅降级。

没有发现 Chinese 姓名判断、宏定义或指令表相关的 bug。

**2026-08-05 §10.7 深度测试追加修复**（`adm/daemons/logind.lpc`，
和 `jyqxc` 自己修复前逐字节相同的两处问题，因为两库实为同一份原始
数据的两份快照——`jyqxc2` 这一份此前没有回灌 `jyqxc` 那一轮的修
复）：

- **AGENTS.md §8.9**：食物/饮水首次登入初始化判断读错对象
  （`ob->query("age")` 应为 `user->query("age")`），导致新角色食
  物/饮水永远卡在 0。
- **AGENTS.md §7.34**：`get_name()` 里紧邻中文名字设定前的调试残留
  `printf("%O\n", ob)`，直接把登录物件内部路径印到玩家屏幕上。

两处均已现场用非管理员抛弃测试角色验证：修复前 `score` 食物/饮水两
栏全空，屏幕上出现裸露的 `/clone/user/login#N`；修复并 `update
/adm/daemons/logind` 热编译后两栏全满，提示行消失。同一次测试还完
整走完一次真实死亡（`kill` NPC 欧阳克）→"鬼门关"两位鬼差 NPC 对话
链未受任何中断→`reincarnate()`→复活于"武庙"的全流程，并确认死亡区
的 `exits`/`valid_leave()` 没有 AGENTS.md §7.101 记录的那种遗漏形
状（唯一出口 `north` 与代码、房间描述"一进鬼门关就无法再回阳间了"
三者一致，是有意的单向门）；死亡 NPC 档案与 `jyqxc` 自己已撤销的
§7.68 分析逐字节相同，现场复核未发现任何强制移走鬼魂的第二套机制，
同样判定为有意设计，不套用旧修复。详见 `NOTES.md`「深度功能测试
