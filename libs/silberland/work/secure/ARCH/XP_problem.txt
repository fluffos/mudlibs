Beim ueberschreiten von 2 Milliarden wird eine Milliarde abgezogen und die
Prop P_MXP (milliarden XP) um eins erhöht. So kanns nie zu einem Ueberlauf
kommen (ausser man bekommt ca 150 millionen xp auf einmal).
In P_XP sind dann auch noch ueber 1 Milliarde XP, was fuer alle Restrictions
reichen sollte. Ueberall wo ein XP-anstieg beruecksichtigt wird, muss dann
die P_MXP property berücksichtigt werden. (zb in den Gilden, aber das ist 
nicht dringend, nur wenn ein Spieler waehrend dem Gildenstufenaufstieg einen 
Milliardenumbruch hat.)

In der Mudlib sinds nur ein paar Aenderungen.

Z1079:

int AddExp(int e)
{
  int experience;

  experience = QueryProp(P_XP);
  if(QueryProp(P_KILLS)>1 && e>0) return experience;
  if((experience+=e) < 0) experience = 0; 
  if((experience) > 2000000000)
  {
    experience -= 1000000000;
    Set(P_MXP,SAVE|PROTECTED|SECURED,F_MODE_AS);
    SetProp(P_MXP, QueryProp(P_MXP) + 1);
  }
  return SetProp(P_XP, experience);
}

Z303:

nomask static int Exp2Lp(int xp)
{
  if (xp <= 0) return 0;
  if (xp > XP_EXPLIMIT)
    return LP_EXPLIMIT + ((xp - XP_EXPLIMIT) / XP_PER_LP) +
    QueryProp(P_MXP) * (1000000000 / XP_PER_LP);
  else
    return to_int (100 * log( to_float( xp + XP_BASE ) / XP_BASE )
                   / log(XP_FACT) );
}
